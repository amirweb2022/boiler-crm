# Domain Docs

Use a single-context layout: `CONTEXT.md` at the repository root and
ADRs under `docs/adr/`.

Before exploring an area, read `CONTEXT.md` and relevant ADRs when they
exist. Proceed silently when they do not. The `/domain-modeling` skill
creates them as terms and decisions are resolved.

Use the glossary's terms when naming domain concepts in issues, proposals,
hypotheses, and tests. If a term is missing, reconsider it or note the gap
for `/domain-modeling`. Surface any conflict with an existing ADR explicitly.
